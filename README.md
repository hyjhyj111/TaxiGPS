# 出租车 GPS 轨迹查询系统

出租车 GPS 轨迹查询系统是一个面向真实出租车时空数据的分析与可视化平台，支持轨迹查询、分钟位置查看、OD 点标注、动画轨迹演示、路线规划，以及热力图与统计分析。

## 功能概览

### 轨迹查询
- 按车辆 ID 和时间范围查询轨迹
- 最多支持 10 辆车并行展示
- 按运营状态自动着色：红色为载客，蓝色为空载
- 优先读取车辆缓存，避免直接扫描原始大表

### 分钟位置
- 查看指定分钟的车辆分布
- 支持按车辆 ID 筛选
- 点击车辆点后可展开该车后续轨迹预览

### OD 点标注
- 展示上车点、下车点及连线关系
- 点位较多时自动聚类，减少拥挤
- 支持抽样展示 OD 路径

### 动画轨迹
- 支持单车和多车轨迹回放
- 支持播放速度调节
- 轨迹按时间顺序平滑播放

### 路网校正与地图选点
- 支持加载深圳道路网络 `shenzhen_drive.pkl` 或 `shenzhen_drive.graphml`
- 支持将 GPS 点匹配到最近道路节点，并用最短路径拼接校正轨迹
- 最短路径绘制会优先展开道路边自带的 `geometry` 折线，避免只连接节点导致轨迹穿过建筑物或河流
- 支持按查询区间复用路网校正缓存：当前查询已被缓存覆盖时直接读取，未覆盖时只补处理缺失区间
- 支持原始轨迹与路网校正轨迹同图对比
- 支持在地图上点击选点并显示经纬度
- 路网校正示例默认限制为 1-3 辆车和短时间窗口，避免一次处理全量车辆

### 路线规划
- 支持复用车辆缓存和既有地图匹配逻辑生成道路边全日基准速度
- 支持为路网道路边写入 `baseline_speed_kph` 和静态通行成本 `route_cost`
- 支持手动输入起终点或使用历史 OD 端点，并吸附到同一套深圳路网节点
- 支持同图绘制最短距离路线和基准最快路线，展示距离、边数和基准成本
- 地图提供连续两次点击的坐标读取面板，便于把任意起终点填回路线查询

### 拥堵道路与 ETA
- 支持近似 HMM 地图匹配：最近道路节点作为发射近似，最短路连续性作为转移约束
- 支持按稳定道路节点对生成路段 key，并按 `5 / 15 / 30 / 60` 分钟聚合路段平均速度
- 支持红、橙、黄、绿固定阈值绘制拥堵道路，低速红色、高速绿色
- 支持动态播放不同时间片的路段速度颜色变化
- 支持输入起终点经纬度，按路网最短路径距离和历史平均速度估算 ETA

### 热力图与统计分析
- 支持分钟缓存车辆位置静态热力图
- 支持 OD 上车点静态热力图
- 支持 `1 / 15 / 30 / 60` 分钟动态热力图
- 支持 `EMA / WMA` 平滑算法
- 支持 DBSCAN 上车点聚类分析
- 支持小时订单统计、里程区间统计、车辆运营统计
- 支持 CSV / Excel 统计导出

## 当前实现说明

### 热力图口径
- 分钟缓存车辆位置静态热力图固定按全部车辆统计，不受左侧车辆 ID 筛选影响
- 分钟缓存车辆位置动态热力图固定按全部车辆统计，不受左侧车辆 ID 筛选影响
- OD 上车点热力图仍按当前车辆筛选条件执行

### 动态热力图
- 已从 `HeatMapWithTime` 切换为自定义 `Leaflet.heat + requestAnimationFrame` 播放器
- 支持时间轴拖动、逐帧插值和平滑播放
- 已加入自适应点数预算控制，用于降低掉帧、闪烁和卡顿

### 静态热力图
- 默认显示范围收紧为深圳展示范围
- 已加入深圳行政边界内点位过滤，减少边界外热力点干扰

### 车辆运营统计
- 当前采用 OD 快速统计口径
- 页面中“总里程估计 / 空载里程估计”为估算值，不是逐轨迹积分值

### 拥堵道路与 ETA 口径
- HMM 为可解释近似实现，未依赖额外 HMM 库
- 路段颜色阈值固定为：`<15 km/h` 红色，`15-25 km/h` 橙色，`25-40 km/h` 黄色，`>=40 km/h` 绿色
- ETA 使用当前查询车辆和时间范围内的匹配路段历史均速；路线缺失路段使用查询样本全局均速，若没有样本则使用默认速度
- 拥堵道路示例默认最多使用 8 辆车和较短时间窗口，兼顾路段覆盖效果与页面响应速度

### 路线规划口径
- 最短距离路线使用道路边 `length` 作为 Dijkstra 权重
- 基准最快路线使用静态 `route_cost` 作为 Dijkstra 权重，不使用出发时间或分时段速度
- `route_cost` 由道路长度和基准速度生成，速度优先级为：车辆缓存匹配样本全日均速、同类 `highway` 中位数、道路类型默认速度、全局回退速度
- 生成的道路边基准速度缓存默认保存为 `cache/edge_baseline_speed.csv`
- 历史 OD 端点会保留原始坐标，路线查询额外展示吸附后的起终点路网节点

### 路网校正缓存口径
- 车辆校正缓存默认保存到 `cache/road_corrected/`
- 缓存文件名包含车辆 ID 和路网文件版本 token；覆盖区间记录在同名 `.coverage.json`
- 每次路网校正先检查当前查询的时间范围是否已被缓存覆盖；覆盖时直接读取缓存，未覆盖时只处理缺失区间并合并缓存
- 校正缓存版本包含道路边几何展开算法，旧的仅节点折线缓存不会被继续复用
- 页面校正统计表会显示 `cache_hit`、`cache_rows`、`window_rows`、`processed_intervals`、`cache_path` 和 `coverage_path`

## 运行前提

- Python `3.13+`
- 已准备车辆缓存、分钟缓存和 OD 结果表
- 已安装 `streamlit`、`folium`、`pandas`、`numpy`、`scikit-learn`、`altair`
- 如需路网校正，需额外安装 `networkx`；如使用 `.graphml` 路网文件，还需安装 `osmnx`

## 使用说明

1. 在左侧选择日期、时间范围和车辆 ID。
2. 点击“执行查询”后切换顶部功能模块。
3. 轨迹查询优先读取车辆缓存，分钟位置优先读取分钟缓存。
4. 在“热力图与统计分析”中可切换静态热力图、动态热力图、订单统计、车辆运营、上车点聚类。
5. 当热力图数据源为“分钟缓存车辆位置”时，系统固定按全部车辆统计。
6. 当热力图数据源为“OD 上车点”时，系统按当前车辆筛选执行。
7. 在“轨迹查询”中可打开“启用路网校正”，对所选前 1-3 辆车展示原始轨迹与校正轨迹。
8. 在“路线规划”中输入起终点或选择历史 OD 端点，可生成最短距离路线和基准最快路线。
9. 在“拥堵与ETA”中选择多辆车和聚合时间片，可查看按时间片播放的路段拥堵颜色，系统默认最多取前 8 辆。
10. 在“拥堵与ETA”中输入起终点经纬度，可生成 ETA 预测结果和路网路线。
11. 地图支持点击选点，左下角面板会显示点击位置的经纬度；路线规划地图支持连续点击起点和终点。

## 数据准备

清洗后的轨迹数据至少应包含以下字段：

- `id`：车辆 ID
- `time`：时间戳，格式 `YYYY-MM-DD HH:MM:SS`
- `long`：经度
- `lati`：纬度
- `status`：状态，`0=空载`，`1=载客`
- `speed`：速度，单位 `km/h`

建议处理流程：

1. 运行 `data_cleaning.py` 完成原始数据清洗。
2. 运行 `clean_od_extraction.py` 提取 OD 上下车点。
3. 首次启动系统时自动构建车辆缓存与分钟缓存。
4. 将深圳边界文件放入 `data/深圳市.json`。
5. 如需路网校正，将 `shenzhen_drive.pkl` 优先放入项目根目录、`data/` 或 `cache/`；也可使用 `TAXIGPS_ROAD_NETWORK_PATH` 指定自定义路径。

## 注意事项

- 地图 HTML 输出目录为 `pages/maps/`
- 统计导出目录为 `exports/heatmap_stats/`
- 分钟热力图和静态热力图都带有边界过滤与漂移过滤
- 动态热力图首次加载后可通过底部时间轴直接拖动查看任意时间片
- 路网校正优先读取 pkl 文件；`nearest_nodes` 使用经度、纬度顺序，查询结果会按覆盖区间写入车辆级校正缓存
- 路线规划优先使用同一路网的有向多重边 `(u, v, key)`，无路径、缺失速度和样本不足会使用明确提示或速度回退
- 拥堵道路与 ETA 复用同一路网文件和匹配逻辑；如需更严格的 HMM，可在近似匹配函数中替换候选点和转移概率计算
